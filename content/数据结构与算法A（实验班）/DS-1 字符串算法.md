# DS-1 字符串匹配
内容：KMP 算法、BM 算法、Shift-And 算法、DFA 以及 AC 自动机。
## $\mathrm I$ KMP 算法
### $\it 1.1$ 问题描述与朴素算法
给定一个长度为 $n$ 的字符串 $S$ 与一个长度为 $m$ 的模式串 $P$，若 $S[i:i+m-1]=P$，则称 $S$ 在位置 $i$ 出现了 $P$。求所有出现位置。

一个朴素的算法是，枚举每一个 $1\le i\le n-m+1$，从当前位置 $i$ 开始将 $S[i:i+m-1]$ 与 $P$ 进行逐个字符的比较，时间复杂度最大为 $O(nm)$。
- 分析：朴素算法有大量算力的浪费，是因为没有利用好已知的信息，造成了资源的浪费，例如匹配到某一个位置 $S[i:i+t-1]=P[1:t]$，发现下一个字符不相等（$S_{i+t}\neq P_{t+1}$）就直接重新回到 $P_1$ 开始匹配。

字符串是一种线性结构。结构。算法要与结构适配。
### $\it 1.2$ KMP 算法的描述
发生形如 $S_{i+t}\neq P_{t+1}$ 的失配之后，如何利用已经相等的 $S[i:i+t-1]=P[1:t]$，是否可以利用这个已知信息快速判断 $S[j:i+t-1]=P[1:t-j+i]$ 相等？
- 假设存在一个 $i<j\le i+t-1$ 使得 $S[j:i+t-1]$ 与 $P$ 的对应长度的前缀匹配，那么有 $P[j-i+1:t]=S[j:i+t-1]=P[1:t-j+i]$。这说明 $P$ 中有“前缀与后缀相等”的现象（当且仅当这是 border）。
- 于是我们受到启发，希望对 $P$ 的每一个前缀 $P[1:t]$ 寻找形如 $P[1:x]=P[t-x+1:t]$ 的关系。那么问题是，满足前缀等于后缀的 $x$ 有很多，在实际匹配的时候应该选择哪一个？（答案是，选择最大的 $x$）我们先对这个问题作一些形式化处理。

**border**。对于 $P$，若其存在公共前后缀 $P[1:t]=P[m-t+1:m]$，则将 $t$ 称为 $P$ 的一个 border（其中 $t<m$）。
- 定理。任取 $x_1<x_2$ 都是 $P$ 的 border，那么 $x_1$ 是 $P[1:x_2]$ 的 border。
	- 证明：$x_1$ 是 border，即 $P[1:x_1]=P[m-x_1+1:m]$。而 $P[m-x_1+1:m]$ 是 $P[m-x_2+1:m]$ 的后缀，根据 $x_2$ 是 border，有 $P[m-x_1+1:m]=P[x_2-x_1+1:x_2]$。也就是说更短的 border $x_1$ 是更长 border $x_2$ 的 border。
- 分析。这说明，如果我们将任意字符串 $P$ 的所有 border 从小到大排成一列，那么其按照“...是...的前缀”形成了一个**全序**。

从 border 的分析可以看出，$P$ 的最大 border 非常关键，假设我们按照线性顺序处理 $P$，那么按照 $P$ 的 border、$P$ border 的 border（相当于 $P$ 某一个前缀的 border）、... 就可以访问 $P$ 的所有 border。于是我们的目标就是求得 $P$ 每一个前缀 $P[1:i]$ 的**最大 border**。

**border 数组**。对于模式串 $P[1:m]$，定义 $N_i$ 表示前缀 $P[1:i]$ 的非自身的最大 border，即形式化地有 $N_i:=\sup\{k<i\mid P[1:k]=P[i-k+1:i]\}$。那么求 $N_i$ 的过程就相当于 $P$ 自己跟自己匹配。

求 border 数组。采用 dp 的方法计算 $N_i$。假设我们已经知道了 $N_2\sim N_t$，需要计算 $N_{t+1}$。根据类似的思路，我们要找一个 $P[1:t]$ 的 border 尝试看其是否能匹配上 $P_{t+1}$。而根据 border 的“全序”关系，我们第一步只用找 $j=N_t$（也就是最大的 border），看看是否有 $P_{j+1}=P_{t+1}$。如果成功匹配，那么说明 $N_{t+1}=j+1$。否则反复 $j\gets N_j$（替换为下一个次大 border）尝试匹配，直到 $P_{j+1}=P_{t+1}$，说明 $N_{t+1}$ 正是 $j+1$。
- 边界处理：若 $P$ 的某个前缀不存在任何 border，则应当将其设为 $0$。若遍历了所有 border 都没能找到成功匹配，那么说明在已经匹配这这一小段中不存在任何 border 现象，于是可以“放心跳过”，重新在下标 $1$ 开始匹配。

```cpp
char p[N];
int n, kmp[N];

int main() {
	scanf("%s", p + 1), n = strlen(p + 1);
	for(int i = 2, j = 0; i <= n; ++i) {
		while(j && p[j + 1] != p[i]) j = kmp[j];
		if(p[j + 1] == p[i]) ++j;
		kmp[i] = j;
	}
	return 0;
}
```
至此我们求得了 $N_i$。考虑原字符串 $S$ 的匹配，这个过程是完全一致的，初始暴力匹配，遇到不匹配的地方就寻求 border。
```cpp
char s[N], p[N];
int n, m, kmp[N];

int main() {
	scanf("%s%s", s + 1, p + 1), n = strlen(s + 1), m = strlen(p + 1);
	/* solving kmp[i] for string p */
	for(int i = 1, j = 0; i <= n; ++i) {
		while(j && p[j + 1] != s[i]) j = kmp[j];
		if(p[j + 1] == s[i]) ++j;
		if(j == m) printf("S[%d, %d] = P\n", i - m + 1, i);
	}
}
```
- 注意这里有一个边界：若 $P[1:m]$ 都与 $S$ 的某个子串完全匹配，那么接下来 `p[j + 1]` 将指向空，这不与任何字符相等，即跳到 `kmp[m]`，这是正确的。
### $\it 1.3$ KMP 失配树与自动机
**失配树**。观察 $N$ 数组，任意的 $N_i$ 都满足 $N_i\in[0, i)$。这启发我们，如果将 $0, 1, \cdots, m$ 视为结点，将 $N_i$ 视为结点 $i$ 的父亲，那么这 $n+1$ 个点形成了一棵树。

**KMP 自动机**。观察这个失配树结构，可以发现这还是一个自动机：结点 $0, 1, \cdots, m$ 是状态，处于状态 $x$ 即表示“当前位置有 $P[1:x]$ 成功匹配”。处于状态 $x$ 时，每次投喂一个新的字符 $c$ 给这个自动机，根据 KMP 的原理，自动机期望 $c=P_{x+1}$，因为这样就可以继续往下匹配，转移到状态 $x+1$。否则匹配失败，需要寻找 border，就跳到 $N_x$（跳父亲），按顺序寻找在所有 border $t$ 中是否存在 $P_{t+1}=c$，否则将跳回 $0$ 节点，表示现在不存在任何匹配。
### $\it 1.4$ 时间复杂度分析
KMP 的复杂度是“均摊”的，其中某一步可能耗时很久，所以要从总体复杂度去分析。若此时在状态 $x$，正在尝试匹配 $P_i$，那么记全局变量 $M=i-x$ 表示“模式串的头的位置”。那么每次匹配失败，跳 border 都可以视为向右挪动 $M$（$M$ 至少增大 $1$）。否则匹配成功，$i\gets i+1$。

考虑到 $M$ 初始为 $1$，至多为 $m$，且 $i\gets i+1$ 也至多发生 $n$ 次，因此总时间复杂度为 $O(n+m)$。
- 对于预处理，其可以视为 $P$ 的自匹配，因此时间复杂度为 $O(m)$。
- 注：这里 $M$ 即为势能函数，势能分析法即为寻找如此的单调变化的变量用来“记账”。
## $\mathrm{II}$ BM 算法
### $\it 2.1$ Intro
KMP 具有非常优秀的理论复杂度 $O(n+m)$，但实际上跑起来却很可能“跑满”，运行起来并不快，实际运行时常慢于朴素匹配（如果字符串随机的情况下，每个位置触发接近 $O(m)$ 匹配的概率很低，以至于 $i$ 很快就从 $1$ 扫到了 $n$）。

原因在于在自然文本中，开头相同的概率高于结尾相同的概率（比如特定语境下都以“Hello”等开头）。而 BM 从右往左比较，失配时利用坏字符和好后缀规则跳跃。自然文本中，模式串末尾字符的分布往往不均匀，坏字符规则一次能跳很远，所以实际效率高于 KMP。
### $\it 2.2$ 算法描述
问题描述：给定文本串 $S[1:n]$ 与模式串 $P[1:m]$，求所有匹配位置 $i$ 使得 $S[i:i+m-1]=P$。

**BM 算法**。BM 算法基于一种很 tricky 的思想，是一种能够较为充分利用已计算信息但不保证最坏复杂度的算法。其基本模式如下：最开始，将模式串与文本串的最左段对齐。按模式串**从后往前逐个匹配**（即从 $m$ 往 $1$ 匹配），若失配，则将模式串往后移动若干步，然后继续下一次匹配，直到跳出文本串的范围。具体而言，有两种计算移动步数的方法：
1. bad character 原则。假设按模式串从后往前匹配，$P[x+1:m]$ 已经与 $S$ 的某处 $S[t+1:\cdot]$ 成功匹配，但 $P_x$ 匹配失败（$P_x\neq S_t$），则令 $c=S_t$ 为导致本次匹配的 bad character。查询在**模式串**中，$c$ 上一次出现的位置 $y$（即：$\sup\{i<x\mid P_i=c\}$），然后将模式串右移使得 $y$ 位置与 $S$ 中原本失配位置 $t$ 对齐。若 $c$ 不在 $x$ 左侧出现，则直接后移 $P$ 使得跳过 bad character $S_t$（$1$-index）。
2. good suffix 原则。假设匹配时 $P[x+1:m]$ 已经与 $S[t+1: w]$ 成功匹配，但 $P_x$ 匹配失败，则此时已经成功匹配的后缀 $P[m:m], P[m-1:m], \cdots, P[x+1:m]$ 为 good suffix。
	- 查询模式串中 $P[x+1:m]$ 上一次出现的地方（注意是整个 good suffix，按结束位置计），若存在这样的 $y$，则将模式串的 $y$ 位置与 $S_w$ 对齐。
		- 注：$y$ 形式化为 $\sup\{y<m\mid P[y-(m-x)+1:y]=P[x+1:m]\}$。
	- 若不存在整串的 $P[x+1:m]$ 出现，那么寻找一个 $P[x+1: m]$ 的（最长的）后缀 $P[m-z+1:m]$，使得其同时为 $P$ 的前缀 $P[1:z]$。如果存在这样的前缀 $P[1:z]$，则将模式串的位置 $z$ 与 $S_w$ 对齐。
	- 若仍然不存在这样的前缀，将 $P$ 的头部移动到 $w+1$，完全跳过 good suffix。
- 实际移动时，取 bad character 与 good suffix 较大的移动位数。
- 注：如果匹配成功，那么按照 good suffix 规则（此时无 bad chararcter），此时的向后跳等价于 KMP 的 border。
### $\it 2.3$ BM 算法分析
容易发现，bad character 原则和 good suffix 原则都是针对匹配的优化，而非 KMP 那样的确定性数学推导，更像是一个朴素算法的“改编”。

其正确性很容易证明：
- 对于 bad character，若当前位置匹配失败，那么在下一个候选的匹配位置，$S_t$ 总要与某个 $P$ 中的字符匹配，故寻找“$c$ 上一次出现的位置”就是在于 $y+1$ 到 $x$ 之间没有能够匹配上 $S_t$ 的字符，因此绝无可能与整个 $P$ 匹配。
- 对于 good suffix，其目的是一定程度利用已经匹配好的 $P[x+1:m]$。依旧设想下一个候选的位置，则其至少要与这个后缀 $S[t+1:w]$ 匹配，因此分两类讨论，即存在一个另外的（且最靠右的）$P[x+1:m]$，或者不存在这样的 good suffix 但存在一个 $P$ 的前缀使得其为 $P[x+1:m]$ 的后缀。否则可以直接跳过这个 good suffix，因为期间绝无可能与整个 $P$ 匹配。
### $\it 2.4$ 算法实现
接下来考虑如何预处理 bad character 以及 good suffix 所需要的信息。注意到**其只与模式串 $P$ 自身有关**，不依赖文本串 $S$。

bad character 的预处理是简单的，只需要从左到右扫一遍，针对每个位置 $x$ 以及每个字符 $c$ 记录 $c$ 上一次出现在哪里，即 $L(x, c):=\sup\{y<x\mid P_y=c\}$。复杂度 $O(m\Sigma)$。
- 实际上如果嫌 $O(m\Sigma)$ 多，可以只考虑处理每一个字符在 $P$ 中出现的最右侧位置（只需要 $O(m+\Sigma)$），如果某一个 bad character $c$ 在 $x$ 的右侧出现了（无法知晓 $x$ 左侧的 $c$ 的情况），那么此时直接移动 $x+1$ 位在工程上也是合理的。此种方法只需 $O(m+\Sigma)$ 的时空。

有关 good suffix 的处理，分为朴素处理与工业处理两种。一般情况下，如果 $P$ 规模不大或者 $P$ 需要反复匹配，此时瓶颈在 $S$ 上，因此 $O(m^2)$ 朴素处理是可以接受的。同样存在基于 Z 算法和 KMP 算法的 $O(m)$ 处理：
- 将 $P$ 翻转为 $P'$（转为前缀）。对 $P'$ 使用 Z 算法得到 $z_i:=\sup\{t\mid P'[1:t]=P'[i:i+t-1]\}$。对每一个前缀 $P'[1:x]$ 求一个最靠前的下标 $y\ge2$ 使得 $P'[1:x]=P'[y:y+x-1]$，也就是求一个最小的 $y$ 使得 $z_y\ge x$。从小到大枚举 $x$，因为 $x$ 单增，所以只用扫一遍 $z$ 数组即可确定所有的 $y$。这对应“存在一个完整出现的前缀”的情形。
- 有关“公共前后缀”，直接使用 KMP 即可。
### $\it 2.5$ 算法复杂度分析以及评价
BM 算法对最坏复杂度没有保证，在刻意构造的数据下可以退化为朴素的 $O(nm)$，如 $S$ 和 $P$ 所有字符都是一样的情况。但是通常情况下其实际的效率要优于 KMP（因为自然文本下后缀相等的概率较小），大多情况下其对齐并尝试匹配的次数在 $O\left( \dfrac nm \right)$ 级别（总体仍是约 $O(n)$ 级别），也就是基本全跳了。

想卡掉 BM 算法是很容易的，只需要 $S=a^n$，$P=a^m$ 即可。一个重要的原因在于 BM 算法完全没有处理**匹配成功**的优化（其本质暴力，对每一处成功的匹配只能老老实实逐个字符比较），其优化都是针对**匹配失败**这一情景的（对比来看，KMP 是“匹配总是成功”的优势区间）。

正因此，其在算法竞赛中几乎无应用（因为毒瘤出题人），但其思想（坏字符、好后缀）以及衍生算法（如 BM-Horspool、Two-Way 算法）在工业界文本搜索（grep、编辑器、数据库 `LIKE`）中占据绝对统治地位——因为自然文本中 99% 以上的对齐尝试都会在最后几个字符内失配，此时 BM 的跳跃优势将发挥到极致。
## $\mathrm{III}$ Shift-And 算法
### $\it 3.1$ 算法描述
Shift-And 算法是一种基于位运算的字符串匹配算法。还是那个问题：给定模式串 $P[1:m]$ 与文本串 $S[1:n]$，求所有出现位置 $x$ 使得 $S[x:x+m-1]=P$。

其基本思想是使用类似 `bitset` 的数据结构进行加速。依次扫描 $S_1$ 到 $S_n$，并维护一个 $m$ 位的布尔数组 $\mathbf a=(a_1, a_2, \cdots, a_m)$。扫描到 $S_i$ 时，$a_j$ 代表 $P[1:j]$ 是否是 $S[1:i]$ 的后缀。
- 进行转移。假设扫描到 $S_i$ 是 $\mathbf a$ 为原始状态，$\mathbf a'$ 为更新后的状态，那么 $a'_j=1$ 当且仅当 $a_{j-1}=1$ 且 $S_i=P_j$。
- 写成整体的位运算即为 $\mathbf a'=[(\mathbf a\ll 1)\lor 1]\land\mathbf f_c$。其中 $\mathbf f_c$ 是一个 $m$ 位布尔数组，其 $\mathbf f_c(i)=1$ 当且仅当 $P_i=c$。
	- 与 $(1)_2$ 取或的原因是保持 $a_0=1$（即 $P$ 的空前缀默认能够匹配）。
### $\it 3.2$ 算法实现
在 C++ 中，使用 `bitset` 来实现上述的布尔数组，对所有 $c\in\Sigma$ 预处理 $\mathbf f_c$，然后设置初始的 $\mathbf a=0$。执行 $n$ 次转移即可，时间复杂度通常是 $O\left( \dfrac{nm}{\omega} \right)$。

Shift-And 算法本质上是在维护一个 NFA。其优势区间在于 $m$ 较小或者 $m$ 恰为 $2$ 的次幂，总之具有一些硬件友好的因素。其在面对小 $m$ 时具有优秀的常数与不俗的运行速度。
## $\mathrm{IV}$ DFA 与 AC-AM
DFA 是几乎所有字符串算法的数学模型，其能够根据输入信息（通常为文本串的字符）来连续调整内部的状态，并基于状态给出结果。
### $\it 4.1$ DFA 的形式定义
**确定有限自动机 DFA**。一个 DFA 可以形式化为一个五元组 $\mathbf D=(Q, \Sigma, \delta, q_0, F)$。
1. $Q$：所有状态组成的集合。
2. $\Sigma$：所接受的所有字母，即字母表或者字符集。
3. $\delta:Q\times\Sigma\to Q$：转移函数，形如 $\delta(q, c)=q'$，也就是处于 $q$ 状态时读取到 $c$，则转移到 $q'$。
4. $q_0\in Q$：起始状态。
5. $F\subseteq Q$：接受状态，一旦 DFA 到达这些点则被视为“接受”（accepted）。

字符串算法中常见的自动机有 KMP、Trie、AC 自动机、SAM、PAM 等。有关自动机涉及一系列常用的分析思路。
### $\it 4.2$ AC-AM 的描述
问题描述：给定文本串 $S$ 与 $n$ 个长度不等的模式串 $P_i$，求所有模式串在 $S$ 中出现的位置。

AC-AM 的想法与 KMP 类似。将这个 $n$ 个模式串插入 Trie 中，此时 Trie 的结点正是自动机的状态：一个结点 $x$ 代表“当前文本串的匹配为从 Trie 根节点到 $x$ 的所有字符” 。
- 考虑如果当前的 $S[p:i]$ 在 Trie 中对应状态 $x$，那么是否存在 $p<q\le i$ 使得 $S[q:i]$ 也能匹配上 Trie 中的另外状态 $y$？这与我们之前的分析一致。
- 类似定义 border：记 $f(a)$ 为从根节点往下走到状态 $a$ 形成的字符串，那么考虑状态 $x$ 和 $y$，若 $f(y)$ 是 $f(x)$ 的后缀，则称 $y$ 是 $x$ 的一个 border。规定 $0$ 结点（Trie 的根）是任何状态的 border。
- 考虑 Trie 中的结点 $a$，$b$。假设存在 $p<q_1<q_2\le i$ 使得 $S[q_1:i]=f(a)$ 而 $S[q_2:i]=f(b)$，那么 $b$ 是 $a$ 的 border。换言之，对于任意的状态 $x$，其所有 border 按照 border 关系形成了**全序**。因此我们只用对 $x$ 记录一个长度最大的 border $y$。我们将其定义为 $y=\mathrm{fail}(x)$。

**fail 的求法**。凭空求一个结点 $x$ 的 fail 是不现实的，我们需要依赖 $x$ 在 Trie 上的父亲 $y$。那么一定存在一个 $y$ 的 border $z$ 使得 $z$ 结点的下方有 $y\to x$ 的字符 $c$。
- 那么一个朴素的求法就是，对于其父亲 $y$ 不断跳 fail 指针，直到找到一个 $y$ 的 border $z$ 使得其存在对应的字符转移。考虑到 Trie 上深度更深结点的 fail 依赖更浅的节点，因此对 Trie 从根结点出发按照 BFS 的顺序求 fail 即可。
- 但是这个做法复杂度没有保障，$y$ 的 border 可能要跳很多次。不过我们发现这个 border 的信息是可以路径压缩处理的，且可以视为 Trie 基本转移的某种扩展。定义 $\mathrm{tr}(x, c)$ 为在 $x$ 处失配且失配字符为 $c$ 时（即结点 $x$ 不支持字符 $c$ 的转移），需要跳到的结点（即 $x$ 的一个最大 border $z$ 使其支持字符 $c$）。
	- 其实可以用 $\mathrm{tr}$ 的定义统一原本 Trie 的转移边：$\mathrm{tr}(x, c)$ 可以读作，首先寻找 $x$ 以及其所有 border 中最大的 border（假设 $x$ 也是一个自身的“border”）$z$ 使得 $z$ 有转移边 $c$，那么 $\mathrm{tr}(x, c)=\mathrm{ch}(z, c)$（这里 $\mathrm{ch}$ 指 Trie 的树边）。从这里直接看出，$\mathrm{tr}(x, \cdot)$ 直接继承 $\mathrm{tr}(\mathrm{fail}(x), \cdot)$。
- 那么有了 $\mathrm{tr}(x, c)$，fail 的信息就可以直接处理，上述跳 fail 的过程可以写成极其简洁的 $\mathrm{fail}(x)=\mathrm{tr}(\mathrm{fail}(y), c)$，其中 $y$ 是 $x$ 在 Trie 上的父亲，而 $c$ 是对应转移的字符。

回到我们的问题。我们现在已经求得了所有的 fail 以及所有的 $\mathrm{tr}(x, c)$，那么面对给定的文本串 $S$，我们只用将 $S$ 中的字符按照顺序喂给 AC-AM，每次走其对应的 $\mathrm{tr}(x, c)$ 即可。然而，值得注意的是，在实际匹配的过程中，如果当前处于状态 $x$，那么 $f(x)$ 的**所有后缀**都处于成功匹配状态。按照 fail 的定义，此时所有的 border 都被成功匹配了。如果对每一个到达的 $x$，每次都遍历其 border，那么这个行为没有复杂度保障。我们需要通过其失配树结构进行优化。
### $\it 4.3$ 失配树与复杂度分析
分析 fail 指针，任意一个状态 $x$ 通过 fail 指针指向的 $y$，其在 Trie 的深度总是小于 $x$，这启发我们，所有的 fail 指针形成了一颗树的结构。我们称其为**失配树**。那么在 AC-AM 中，其不断跳 fail 的流程就可以视为在失配树上不断跳父亲。

考虑 4.2 结尾的问题，若 $x$ 被到达了，那么其所有 border 就是其在失配树上的所有祖先。此时 $x$ 及其所有祖先都成功匹配了，所以如果问题只要求输出匹配的次数，那么相当于给 $x$ 在 fail 树上的祖先“全部匹配次数 +1”。这显然可以优化，即第一遍处理 $S$ 的时候只对 $x$ 自身进行标记，然后在 fail 树上，一个状态真正被匹配了多少次即为其 fail 子树内的标记数量之和。

最后是终点标记。在 Trie 一开始建立的时候就对每个状态标记“这是否是一个字符串的终点”。按照上述解法处理即可。

**复杂度分析**。
- 预处理 fail 以及 $\mathrm{tr}(x, c)$：需要一次对 Trie 的 BFS，以及每个节点的每个字符（$\mathrm{tr}$）都需要处理，复杂度 $O(|\mathrm{Trie}|\cdot|\Sigma|)$。其中 $|\mathrm{Trie}|\le\sum\limits_{i=1}^n|P_i|$。
- 由于这里跳 fail 的过程被统一到了 $\mathrm{tr}(x, c)$ 中，所以 AC-AM 每次输入一个字符都只会机械转移一次，复杂度是 $O(|S|)$ 的。
- 注意：如果要求输出所有模式串的所有匹配位置，那么就只能采用“每到一个 $x$，就遍历其所有的 fail”的做法或者对 fail 树上的每一个节点开 `vector` 等方式记录。鉴于输出的信息量就是 $O(总出现次数)$ 的，因此没有更优的处理方法。

**势能分析**。考虑这样一个问题：如果只允许一点一点跳 fail（而不是实际直接走 $\mathrm{tr}$），那么复杂度是什么？答案是线性的。考虑将当前结点 $x$ 的深度 $M$ 作为全局势能函数，那么每次输入一个 $S$ 中的字符，$M$ 至多加 $1$，而每次跳 fail 时 $M$ 至少减 $1$，因此跳 fail 的数量不会超过 $|S|$ 次。
